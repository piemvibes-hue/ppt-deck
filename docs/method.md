# PPT 制作方法论：评审导向的演示文档

做过 8 版迭代、按评分表被审过 4 次、模板驳回过 1 次的完整教训沉淀。按顺序走。

---

## 0. 先校准：模板原文 > 你的偏好

评审/比赛的官方模板不是建议，是契约。`inspect-template.py` 第一件事就是把模板正文文本读出来——「内容需包含作品背景、技术实现方式、作品使用场景、未来完善方向四大板块」这种句子是硬性要求，逐字抄下来，后面每页归属一个板块，标题带板块名。我们自己 v8 曾自创版式被判「没用官方模板」重做过——**直接 `Presentation(模板.pptx)` 加页**，不要仿版式。

## 1. 页面表先行：每页 = 一个评审问题

写一张三列表给用户确认再动手：

| 页 | 评审问题 | 证据 |
|---|---|---|
| 3 | 为什么需要这个？ | 痛点数字 + 场景图 |
| 6 | 凭什么信？ | Agent 轨迹截图 + 护栏机制 |
| 10 | 好用吗？ | 一案到底实拍流程 |
| 15 | 达到标准吗？ | 评估数字表+口径 |

- 反例：按功能目录排页（评委记不住"功能很多"，记住的是"这东西怎么帮我"）
- 正解：四板块每块内部按评分逻辑排——背景=必要性、技术=可信度、场景=可用性、未来=延展性
- 页数：模板没写就 15–18 页；封面+THANKS 占 2，正文 13–16

## 2. 内容写法：数字带口径，诚实标注栏

- 每个上屏数字都要有出处：评测结果文件名+复核日期写在备注栏——评委追问「95.7% 怎么算的」你能答
- **诚实标注栏**（v7 起被评审认可的关键设计）：评估页列「口径/样本/方法」，含打平项（「已知题面准确率与基线打平」）——报喜不报忧的表反而降低可信度
- 每页备注栏写讲稿三段：主张（一句话）/ 口径（数字怎么来的）/ 追问应答（评委可能问什么）

## 3. 截图管线

- 全景 `dsf=2`，组件裁切 `dsf=3`——约 390dpi 上屏
- 折叠卡片/异步面板**先点开再截**：Agent 轨迹卡、合规警告条这类组件不点不开
- 有交互证据的状态先制造：填入一段话术、触发一次拦截、让一个 toast 出现——截图里有「正在发生」的痕迹比干净界面可信
- 截错重来不心疼：我们一页 Agent 轨迹配错过图（截了建议卡），发现即重截

## 4. 构建原则

- `browser()` helper 读图原比例 contain-fit——**永远不许把图塞进固定框**，拉伸变形是最低级的失分点
- 每页一种套路别混搭：demo_slide（左图右点）/ duo_slide（双图）/ 卡阵（纯要点）；视觉上让评委预期稳定
- 字：标题 ≤6 字防换行撞行，正文行距 1.4，段内混排用 `tx()` 多 run
- 图层顺序：先 panel 后 text——脚本里顺序即 z 序

## 5. QA 双门禁

- `render.sh` 逐页 PNG，**每张亲眼过**：文字溢出卡片/贴住底条/叠压/拉伸。我们每版都修出 4-6 处
- `qa-deck.py` 口径门禁：必检数字在位（写来源注释）+ 占位词/乱码零命中 + 页数断言
- 做完把页面表按板块复核一遍：四大板块各有归属页、比例合理

## 6. 迭代节奏

评审意见回来 → 先改页面表（结构层）再改构建（表现层）。v7→v8 的教训：修了 6 处视觉细节但叙事没动，分数没涨——**结构问题不要拿版式优化糊弄**。

## 坑位全清单

| 症状 | 根因 |
|---|---|
| 图糊 | dsf=1 裁切 |
| 图变形 | 硬塞 16:9 框 |
| 中文宋体 | 漏设 ea typeface |
| 标题撞行 | >6 字标题两栏各自换行 |
| 叠压 | 后画的盖住先画的 |
| 「没用模板」 | 自绘版式没继承母版 |
| 数字被追问 | 备注栏没写口径 |
| 结构平淡 | 按功能目录排页 |
| 占位残留 | 没跑 qa-deck 禁用清单 |
| 投影看不清 | 正文 <14pt：演示文档字号地板正文 12.5 / 小标题 15 / 页标题 ≥27，放不下就砍字不许缩字号 |
| bullet 挤成竖条 | 图文页文字栏 <2in：双图页图宽让位给文字栏（如 4.15in 图 + 2.7in 文） |
| 两页撞图 | 同一张截图复用两次——每页配图必须独一无二，换角度重裁 |
| 细节塞版面 | 口径/推导写备注栏，版面只留结论 |
